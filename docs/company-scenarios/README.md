# Company Scenarios

These are realistic briefs modelled on what a security engineering team
actually requests. Each scenario includes:

- **Objective** — what the company needs and why
- **Deliverable** — the exact binary or report they expect
- **Skills required** — which modules you need to have completed
- **Constraints** — rules the deliverable must follow
- **Test plan** — how to verify it works

## How to use these

1. Read the scenario brief.
2. Try to design the solution yourself before looking at which modules are referenced.
3. Build it using only the knowledge from those modules.
4. Test against the test plan.
5. If a company gave you this brief, could you deliver it? That's the bar.
